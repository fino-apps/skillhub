# SkillHub 产品与架构方案

## 1. 目标与当前状态

SkillHub 是面向个人的本地 Skill 管理工作台，统一管理自有 Skill 与 GitHub 公开 Skill，支持分类查找、版本维护、项目导入、安装命令生成及目录级差异比较。优先支持 Codex，并遵循 [Agent Skills 格式](https://agentskills.io/specification)。

当前仓库是 Fino 初始化项目：`proto/skillhub/resource.proto` 和 `proto/skillhub/v1/skillhub.proto` 仅包含示例 Resource；`fino.yaml` 未启用数据库等设施；`go/`、`backend/`、`frontend/` 尚未生成。README 描述的是生成后可运行的示例，并非 SkillHub 已实现的功能。本文是目标设计，不表示功能已经存在。

## 2. 使用流程

- **整理个人 Skill**：创建或从本地目录、业务项目导入完整 Skill，维护名称、说明、分类和标签；修改后创建带说明的版本快照。
- **收藏公开 Skill**：录入 GitHub 仓库、Skill 路径及引用，记录解析到的 commit；支持按需查看内容、检查更新和收藏新版本，不默认保留第三方 Skill 副本。
- **项目与管理库同步**：输入本机项目绝对路径，扫描 `.agents/skills/` 和 `.codex/skills/`（兼容指向项目内 `skills/` 的目录符号链接）；展示新增、未变化和已变化项，先比较再选择导入。缺少共同基准时不声称能自动判断冲突。
- **安装到项目**：选择 Skill、版本和项目级或全局范围，复制生成的 [Vercel Skills CLI](https://github.com/vercel-labs/skills) 命令，在目标项目终端执行。生成命令不代表安装成功；重新扫描才确认实际状态。
- **比较与回退**：比较个人快照、当前内容、项目目录或 GitHub 指定引用；查看增删改文件和文本差异，二进制文件仅提示变化。恢复旧版本前先保存当前内容，线上比较不覆盖本地文件。

## 3. 数据与版本

### 个人 Skill

- 每个 Skill 保留符合规范的完整目录，`SKILL.md` 是内容与 Agent 发现入口；前置元数据中的 `name` 与目录名一致。分类、标签和备注属于管理库元数据，不改写上游规范字段。
- 当前内容与不可变版本快照分开保存；快照包含 Skill 内所有选定文件、版本标识和说明。快照内保留原 Skill 名称目录，确保作为 CLI 本地来源时目录名与 `name` 一致。创建快照前检查版本标识唯一，恢复操作先生成当前内容的保护快照。
- 版本采用用户填写的可读标识，附创建时间、说明和内容摘要；摘要基于完整目录的相对路径和文件内容，用于比较而非替代快照。

### 公开 Skill

- 一条目录记录包含仓库地址、Skill 在仓库内的路径、Skill 名称、分类、标签、备注以及已收藏引用和对应完整 commit SHA。安装和复现优先使用 commit SHA；分支和 tag 仅作为来源标签，并在每次获取时显示实际 commit。
- 检查更新由用户发起，拉取到临时目录后比较；不可达、引用失效或网络失败时保留已保存的记录。公开 Skill 不自动复制进管理库，也不自动执行脚本。
- 用户可在查看许可后显式复制为个人 Skill，保留来源、commit 和许可文件，随后作为独立个人 Skill 维护。

### 项目关联

- 本机项目路径与上次成功导入的 Skill 内容摘要及对应快照建立关联。再次扫描时，基于共同基准比较项目和管理库两侧：双方均变化时标记冲突；没有基准时只展示两侧差异，要求用户确认。
- 导入、恢复和删除前展示影响范围；默认排除 `.git`、依赖目录及常见凭据文件，疑似敏感文件在预览中提示，用户明确选择后才复制。删除目录记录与删除个人 Skill 实体分开确认。
### 持久化与一致性

- SQLite 保存 Skill、分类、标签、来源引用、版本元数据和项目同步基准；个人 Skill 当前内容与不可变快照保存在独立文件目录，数据库只保存受控的相对路径和摘要。数据目录可配置，不使用仓库现有 `skills/` 作为用户数据目录：该目录是 Fino 随项目安装的开发技能。
- SQLite 的事务无法同时覆盖文件操作。导入、创建快照和恢复先写入同一文件系统的暂存目录并校验，再以原子重命名发布，最后提交数据库记录；失败清理暂存或未引用文件。启动时检查未完成操作及缺失引用，保留现有数据并提示修复，不静默删除。
- 单用户本地使用 SQLite，启用外键并优先复用 Fino 的 SQLite 配置和生成的仓储能力；模型演进需可重复迁移，启动失败时保留数据库并报告错误。使用数据库唯一约束保障同一 Skill 的版本标识不重复。
- 备份同时包含一致的 SQLite 数据库和整个 Skill 文件目录；首版通过停止服务后同时备份数据库及文件目录来保证一致性；不能在 WAL 模式运行中只复制主数据库文件。业务项目绝对路径是本机信息，迁移后需重新关联。

## 4. Fino 架构

```text
浏览器：分类搜索、详情编辑、导入预览、版本与 diff
       ↓ 生成的类型化 API 客户端
Fino HTTP / gRPC 接口（proto/ 为契约源）
       ↓
Go 应用层：参数、用例编排、错误转换
       ↓
领域与适配器：Skill / 版本 / 项目关联、SQLite 仓储、文件存储、GitHub 只读获取、目录比较、安装命令
       ↓
SQLite、Skill 文件目录、用户选定的业务项目、临时目录、GitHub
```

- 业务契约先定义在 `proto/skillhub/` 和 `proto/skillhub/v1/`；模型与 API input/view 分离。围绕 Skill、版本、项目扫描与导入、对比、上游引用解析和安装命令设计最小必要 RPC，避免将文件系统或 Git 操作伪装成普通 CRUD。
- 示例 Resource 没有真实调用方时，随业务契约替换并清理其引用。`package.yaml` 保持包身份和依赖事实源，`fino.yaml` 管理服务基础设施；实施时将 `backend.skillhub-server.infra.database` 设为 `sqlite`，使用 Fino 生成的 SQLite 基础设施和仓储扩展点；Skill 文件仍由 Go 文件适配器管理，不启用缓存或对象存储。现有配置尚未启用 SQLite，本文不代表其已实施。
- 在 Fino 项目扩展点实现用例和领域规则；路径访问、文件复制、临时目录与远程获取放在明确的适配器边界。生成文件、`.fino/ir/` 和 `DO NOT EDIT` 内容只通过责任源与 Fino 生成器更新。
- 前端通过生成客户端访问契约，复用 Fino 应用外壳；从零搭建时保留默认页眉，仅将天鹅 Logo 右侧名称替换为 SkillHub。列表、详情、项目导入和 diff 作为项目自有页面与组件，避免自行搭建通用页面引擎。
- 安装使用官方 `skills` CLI，而非自行实现安装器。命令构造需要正确引用含空格的路径并支持多个选中 Skill；个人快照使用绝对路径，公开版本使用可复现的上游引用。首版面向 macOS 终端生成命令，文档注明作用域和复制后手动执行。
- 服务默认仅监听回环地址，项目目录访问仅针对用户明确提供的路径；拒绝路径穿越；扫描时允许 `.agents/skills` 等入口链接指向同一项目内的 `skills/`，解析真实路径后按目标去重，拒绝指向项目外部的入口链接以及 Skill 内越出该 Skill 根目录的链接。远程获取仅支持公开 GitHub 来源，不执行下载内容，临时文件在任务结束后清理。

## 5. 界面与边界

- 首页为可搜索、分类和标签筛选的 Skill 列表，明确区分个人与公开来源；详情集中展示内容、来源、版本、项目使用和安装入口。
- 导入界面支持路径输入、扫描结果、文件预览和批量选择；差异界面显示文件列表与并排文本差异，并标识双方来源和版本。
- 全部操作以本地单用户为默认场景，不做账号、团队协作、云同步或自动提交 Git。管理库和已安装副本不会自动互相覆盖；更新已有安装需要用户重新执行安装命令并处理目标冲突。
- 本地快照不是异地备份。数据目录包含 Skill 文件和本机路径，迁移时需重新选择项目路径；是否提交或上传由用户自行决定。

## 6. 实施顺序与验收

1. **契约和骨架**：替换示例契约，设计必要的业务请求和视图，并在 `fino.yaml` 启用 SQLite；运行 `fino doctor --output=. --targets=api,service,frontend`，再生成相同目标，检查生成文件归属与扩展点。
2. **管理与版本**：实现 SQLite 仓储与迁移、Skill 文件存储、导入编辑、分类检索、快照及恢复；验证重启后仍可读取，重复名称、操作失败及中断恢复不覆盖数据。
3. **项目工作流**：实现项目扫描、导入预览、基准比较和冲突提示；验证新增、无变化、单边变化、双方变化以及没有共同基准的情况。
4. **公开来源与 diff**：实现 GitHub 引用解析、临时读取和版本对比；覆盖网络失败、不可用引用、文件增删、文本与二进制文件，以及指向项目内部的入口符号链接。
5. **安装与交付**：生成本地及公开来源的项目级 / 全局命令；验证路径含空格、版本锁定、Codex 目标与多选命令。更新 README，说明启动、数据位置、备份、导入、比较和安装。

按改动运行 `go -C go test ./...`、`go -C backend test ./...` 和前端 `npm run build`；生成后首次构建前端先执行 `npm ci`。核验 SQLite 全新建库和升级、数据库与文件中断恢复、完整备份还原、导入和恢复不会静默覆盖，服务实际仅绑定回环地址，并进行一次端到端的导入、建版本、比较和生成安装命令验证。CLI 需要 Node.js 22.20 或更高版本；当前机器为 Node.js 20，实际安装验证需先满足工具链要求。最后检查 `git diff --check`，不提交代码。

## 7. 方案审查结论

整体方案适合本地单用户场景：Fino 负责契约、服务骨架与 SQLite 集成，SQLite 管理可查询元数据，文件系统保存 Skill 的原始内容与版本快照，安装和差异展示复用成熟工具。需要在实施中重点验证以下边界：

- SQLite 与文件系统不共享事务；暂存、发布及重启恢复流程须结合故障注入验证，不能仅凭数据库事务宣称原子性。
- Fino 的项目级技能可能通过符号链接暴露；扫描必须遵循本方案的范围限制，并避免重复收录。
- 历史版本安装必须指向不可变的个人快照或公开 commit；分支名、tag 和用户复制了命令都不足以证明目标项目实际安装了指定版本。
- 当前项目尚未生成服务或前端，SQLite 配置、迁移、链接扫描及 CLI 版本行为均需在实际实施后验证；本文不是已通过运行验证的实现说明。
